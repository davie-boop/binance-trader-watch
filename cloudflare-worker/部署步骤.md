# Cloudflare Workers 定时触发部署步骤

比 cron-job.org 稳定：Cron Triggers 是 Cloudflare 平台原生定时器，不依赖第三方轮询；
海外节点直连 `api.github.com`，没有国内到 GitHub 的网络波动。

## 前置条件

- 一个 Cloudflare 账号（免费版即可，邮箱注册：https://dash.cloudflare.com/sign-up）
- Node.js 18+（本机已是 v22，无需额外安装）
- 你的 GitHub Fine-grained PAT（就是写在本地 `.cron.env` 里的那个）

> 免费额度：Workers 每天 10 万次请求，本项目每 15 分钟一次 = 每天 96 次，绰绰有余。

## 第一步：安装并登录 Wrangler

在本目录（`binance-trader-watcher/cloudflare-worker`）打开终端，执行：

```bash
npm install -g wrangler
wrangler login
```

`wrangler login` 会打开浏览器让你授权 Cloudflare 账号，确认即可。

## 第二步：写入 GitHub Token（secret）

```bash
wrangler secret put TW_GITHUB_TOKEN
```

提示输入时，粘贴你的 PAT（与 `.cron.env` 里 `TW_GITHUB_TOKEN=` 后面的值相同），回车。
token 只存在 Cloudflare 的加密环境变量里，**不会写进代码或仓库**。

## 第三步：（可选）改交易员列表

默认已内置当前 5 位交易员。若以后在 GUI 里增删了交易员，需要同步到这里二选一：

- **方式 A（推荐）**：设 secret 覆盖，不用改代码：

  ```bash
  wrangler secret put TRADER_IDS
  # 输入逗号分隔的 ID，例如：
  # 5075281354358777856,5261429206216458753,5285947977434857729,5305355976370339073,5312928647505109504

  wrangler secret put TRADER_LABELS
  # 输入 JSON，例如：
  # {"5075281354358777856":"熬鹰资本","5261429206216458753":"爽翻翻","5285947977434857729":"金木爱交易A","5305355976370339073":"金木爱交易B","5312928647505109504":"金木爱交易C"}
  ```

- **方式 B**：直接编辑 `worker.js` 顶部的 `DEFAULT_TRADER_IDS` 和 `DEFAULT_TRADER_LABELS`。

## 第四步：部署

```bash
wrangler deploy
```

成功后会输出 Worker 地址，形如：
`https://binance-trader-watch-cron.<你的账号名>.workers.dev`

`wrangler.toml` 里已配置 `crons = ["*/15 * * * *"]`，部署后定时自动生效，无需额外操作。

> **首次部署若提示 "You need to register a workers.dev subdomain"**：
> 说明账号还没设过子域名（每个账号只需做一次）。打开：
> https://dash.cloudflare.com/ae2c6a5f9183f99642b174eb38d496e4/workers-and-pages
> 在 **Workers & Pages** 页面找到 **Your subdomain** 一行，点 **Change**，
> 填一个子域名（如 `binance-trader-watch`）保存，然后重新执行 `wrangler deploy`。
>
> 注意：旧的 `/workers/onboarding` 链接已失效，会返回 404，不要再使用。

## 第五步：立即测试一次

浏览器打开（把域名换成你自己的）：

```
https://binance-trader-watch-cron.<你的账号名>.workers.dev/trigger
```

应看到 JSON 结果：

```json
{
  "ok": true,
  "status": 204,
  "trader_count": 5,
  "response": "",
  "time": "..."
}
```

- `ok: true` + `status: 204` = GitHub 已收到抓取请求。
- 到 Actions 页面确认出现新的 `workflow_dispatch` 且日志显示「交易员=5」：
  https://github.com/davie-boop/binance-trader-watch/actions

## 第六步：验证定时是否生效

等下一个 15 分钟整点（UTC 的 :00/:15/:30/:45，即北京时间的 :00/:15/:30/:45），查看：

1. Cloudflare Dashboard → Workers and Pages → 你的 Worker → Logs：有 Cron 触发日志；
2. GitHub Actions：每 15 分钟自动多一条 `workflow_dispatch` 运行。

两者都出现即代表接管成功。

## 部署成功后：关掉 GitHub 自带 schedule

避免两个源重复触发（重复不会重复推微信，但会多耗 Actions 分钟数）。
编辑 `.github/workflows/fetch.yml`，把这两行注释掉：

```yaml
#  schedule:
#    - cron: '1,16,31,46 * * * *'
```

保留 `workflow_dispatch:`，因为 Worker 和本地 exe 都走这个入口。

## 常用命令

| 命令 | 作用 |
|---|---|
| `wrangler deploy` | 部署 / 更新 Worker |
| `wrangler tail` | 实时查看 Worker 日志（排查定时任务是否触发） |
| `wrangler secret put TW_GITHUB_TOKEN` | 更新 token（PAT 到期时） |
| `wrangler secret list` | 查看已设置的 secret 名称 |
| `wrangler delete` | 删除 Worker（停止定时） |

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 访问 `/trigger` 返回 `ok:false, status:0` | token 没设好，重跑 `wrangler secret put TW_GITHUB_TOKEN` |
| `status: 401 / 403` | PAT 过期或权限不足，重新生成 Fine-grained PAT（该仓库 Actions: Read and write），更新 secret |
| `status: 404` | 仓库名或 workflow 名不对，核对 `worker.js` 里的 `DISPATCH_URL` |
| `status: 422` | Body 格式或分支问题，确认 `ref: main` |
| 204 但 Actions 没反应 | 等 10–30 秒刷新；仍无则 `wrangler tail` 看日志 |
| Cron 到点没触发 | 在 Dashboard 确认 Worker 的 Triggers 里有 cron；执行 `wrangler tail` 观察下一个整点 |

## 与本地 exe 的关系

- Worker 部署后：电脑关机也能每 15 分钟抓取，这是主力。
- 本地 exe 的「本地定时任务」变成备用：只在窗口开着且点了「启动定时」时工作。
- 两者同时开不会重复推微信（`cloud_state.json` 去重），但建议只保留一个定时源。

## PAT 到期提醒

Fine-grained PAT 默认 90 天有效。到期前 7 天：

```bash
wrangler secret put TW_GITHUB_TOKEN
```

同时更新本地 `.cron.env`（给 exe 用），然后访问一次 `/trigger` 验证。
